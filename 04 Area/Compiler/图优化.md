## 1. 算子融合与合并

### 1.1 Conv1x1 + Convkxk 融合（`Conv1x1Convkxk2dMerge`）

**源码位置**：`Conv.cpp:164`

**作用**：将连续的两个 2D 卷积（前一个是 `1×1`，后一个是 `k×k`）合并为**单个卷积**。

**原理**：

在深度学习网络中，常见的 Bottleneck 结构（如 ResNet、MobileNet）会先通过 `1×1` Conv 降维/升维，再通过 `3×3` Conv 提取空间特征。从数学上看：

```
output = Conv_kxk( Conv_1x1(input) )
       = input * (W_1x1 ⊗ W_kxk)
```

其中 `⊗` 表示卷积的组合。由于卷积满足结合律（在特定条件下），可以将两个卷积核在编译期合并成一个等效的卷积核，从而把两次内存遍历和计算压缩成一次。

**匹配条件**：
- 当前 Conv 是 `k×k`（`k > 1`），输入来自另一个 Conv
- 前一个 Conv 必须是 `1×1`，且**只有一个使用者**（无分支）
- 两个 Conv 的 `group` 都为 1（普通卷积）
- 两个 Conv 都**没有 padding** 和 **ReLU**
- 数据类型为 F32 或 F16

**权重合并计算**：

```
# 前一个 Conv1x1: [D, C, 1, 1]
# 当前 Convkxk:  [E, D, K, K]
# 合并后:        [E, C, K, K]

# 1. 将 Conv1x1 的 weight 转置为 [C, D, 1, 1]
# 2. 对每个空间位置 (k1, k2)，做矩阵乘法:
#    merge_filter[e, c, k1, k2] = sum_d( filter_kxk[e, d, k1, k2] * filter_1x1[d, c] )
```

代码中使用 OpenMP 并行化外层循环 `eckk = E * C * K * K`，每个线程计算输出 feature map 中一个 `(e, c, k1, k2)` 位置的值。

**收益**：
- 减少一次完整的 feature map 读写（内存带宽节省约 30-50%）
- 减少一次中间结果的内存分配
- 对 TPU 后端更友好，减少 layer 间数据搬运

### 1.2 MatMul + Add → MatMulWithBias（`MatMulWithBias`）

**源码位置**：`MatMul.cpp:16`

**作用**：将 `MatMul` 后接一个 `Add（bias）` 的模式，合并为带 `bias` 输入的 `MatMulOp`。

**图示**：

```
MatMul(A, B) -> Add(result, bias_weight)
        |
        v
MatMul(A, B, bias=bias_weight)
```

**匹配条件**：
- MatMul 的 `bias` 操作数当前为 `None`
- MatMul 只有一个使用者，且是 `AddOp`
- Add 的两个输入中有一个是 `WeightOp`（即 bias）
- Bias 的元素个数等于 MatMul 输出的列数 `N`

**原理**：

TPU/NPU 的矩阵乘法硬件通常原生支持 **bias 累加**（`C = A × B + bias`），在指令级别是单条或融合操作。如果在 IR 层面把 Add 合并进 MatMul，后端 codegen 可以直接生成带 bias 的指令，避免一次额外的内存读写和加法运算。

---

### 1.3 BatchNorm → Scale 转换（`TopBatchNormToScale`）

**源码位置**：`BatchNorm.cpp:16`

**作用**：在推理阶段，将 `BatchNorm` 算子完全转换为等价的 `Scale` 算子。

**原理**：

BatchNorm 的推理公式为：

```
y = (x - mean) / sqrt(variance + eps) * gamma + beta
  = x * [gamma / sqrt(variance + eps)] + [beta - mean * gamma / sqrt(variance + eps)]
  = x * scale + bias
```

由于 `mean`、`variance`、`gamma`、`beta`、`eps` 在推理时都是**已知常量**，可以在编译期预计算出 `scale` 和 `bias`：

```cpp
scale[i] = gamma[i] / sqrt(variance[i] + eps)
bias[i]  = beta[i] - mean[i] * scale[i]
```

**收益**：
- `Scale` 算子比 `BatchNorm` 更轻量（只需一次乘加，无需减均值和除方差）
- 后续 `Scale` 还可以进一步与前面的 `Conv` 或 `MatMul` 融合（weight 合并）
- 这是推理优化的**标准做法**，几乎所有推理框架都会做此转换

---

### 1.4 Scale + Scale 融合（`TopMultiScaleMergeToOne`）

**源码位置**：`Scale.cpp:15`

**作用**：连续两个 `Scale` 算子（`y = (x * s1 + b1) * s2 + b2`）合并为一个 `Scale`。

**原理**：

```
output = (input * s1 + b1) * s2 + b2
       = input * (s1 * s2) + (b1 * s2 + b2)
       = input * s_merged + b_merged
```

两个 Scale 的 `scale` 和 `bias` 都是 `WeightOp`，编译期直接做逐元素乘法/加法，生成新的 weight，然后删掉中间的 Scale。

**收益**：
- 减少一次 feature map 的全量读写
- 后续还可能与 Conv/MatMul 继续融合

---

### 1.5 Permute-MatMul-Permute 优化（`PermuteMatMulPermute`）

**源码位置**：`MatMul.cpp:529`

**作用**：消除 MatMul 前后对称的 `Permute{0,2,1}`（即 transpose），直接在 weight 上做 transpose，省去运行时维度重排。

**图示**：

```
Permute{0,2,1} -> MatMul(A, B) -> Permute{0,2,1}
            |
            v
MatMul(A, B_transposed)   # 直接在 weight 上 swap dim
```

**匹配条件**：
- MatMul 的左操作数 `A` 是 `WeightOp`（常量 weight）
- MatMul 前后各有一个 `PermuteOp`，且 order 都是 `{0, 2, 1}`
- MatMul 只有一个使用者

**原理**：

对于矩阵乘法，`transpose(A) × B` 等价于在 weight 数据层面做维度交换。由于 A 是编译期已知的 weight，可以直接读取数据、按新顺序重组、写回新 weight，从而省掉两个 Permute 操作。

## 2. 算子分解与转换

### 2.1 Einsum → MatMul/Reshape（`ConvertEinsum`）

**源码位置**：`Einsum.cpp:15`

**作用**：将 `Einsum` 算子按模式分解为更基础的 `MatMul`、`Reshape`、`Mul`、`Add` 等算子组合。

**背景**：

`Einsum`（爱因斯坦求和约定）是 PyTorch/TensorFlow 中极其灵活的张量运算 API，但 TPU/NPU 通常**没有原生 Einsum 指令**。因此必须在编译期将其分解为硬件支持的基础算子。

**分解示例**：

| Einsum 模式 | 分解结果 |
|------------|---------|
| `"a,b->ab"` | `Reshape(a→[A,1]) + Reshape(b→[1,B]) + MatMul` |
| `"ab,ab->a"` | `Reshape→3D + MatMul + Reshape` |
| `"ab,acb->ac"` | `Reshape→4D + BatchMatMul + Reshape` |
| `"abcd,abce->abde"` | `Reshape + MatMul + Reshape` |
| `"bnhkd,bmvhd->bknqv"` | `Transpose + Reshape + MatMul`（Attention 相关） |

**原理**：

Einsum 的核心是**维度对齐 + 广播 + 求和**。编译器通过字符串解析出每个输入/输出维度，然后：

1. 用 `Reshape` 把相关维度合并成矩阵乘法的 `(M, K)` 和 `(K, N)`
2. 插入 `Permute/Transpose` 调整维度顺序
3. 执行 `MatMul` 或 `BatchMatMul`
4. 最后用 `Reshape` 恢复目标形状

**收益**：
- 将灵活的 Einsum 映射到 TPU 硬件原生支持的算子集
- 为后续的 MatMul 优化（tiling、量化）创造条件

---

### 2.2 Concat → Depth2Space（`ConcatToDepth2SpacePattern`）

**源码位置**：`Concat.cpp:109`

**作用**：将对同一张特征图做空间切片（Slice）再通道拼接（Concat）的模式，识别为 `Depth2Space` 算子。

**图示**：

```
Input [N, C, H, W]
  |-- Slice[0:H/2, 0:W/2] --\
  |-- Slice[0:H/2, W/2:W] ---\__ Concat(axis=C) --> [N, 4C, H/2, W/2]
  |-- Slice[H/2:H, 0:W/2] ---/
  \-- Slice[H/2:H, W/2:W] --/

等价于:

Depth2Space(Input, block_h=2, block_w=2)
```

**典型场景**：
- YOLO 系列中的 **Focus 模块**
- 某些上采样/像素重排操作

**原理**：

`Depth2Space`（也叫 Sub-pixel / PixelShuffle 的逆操作）的语义正是：将空间维度的数据重新排列到通道维度。当 Concat 的输入全部来自对同一张图的 `2×2` 或 `3×3` 网格切片时，完全等价于一个 `Depth2Space`。

**扩展模式**：

- `ConcatToDepth2SpacePattern2`：支持 NHWC 格式和更复杂的 slice 顺序（含 transpose）
- 如果 slice 顺序被打乱，pattern 还会**重写后续 Conv 的 filter weight**，做对应的通道重排，保证语义一致

**收益**：
- `Depth2Space` 在 TPU 上通常有专门的 DMA/数据搬运指令，比通用的 Slice + Concat 更高效
- 减少中间 tensor 的内存分配

---

### 2.3 Permute → PixelShuffle / Reorg（`TopPermuteToPixelShuffle`、`TopPermuteToReorg`）

**源码位置**：`Permute.cpp:21`、`Permute.cpp:100`

**作用**：识别 `Reshape + Permute + Reshape` 的三元组模式，替换为专门的 `Depth2Space`（PixelShuffle）或 `Reorg` 算子。

**PixelShuffle 示例**：

```
Reshape:   [1, 128, 64, 64] -> [1, 32, 2, 2, 64, 64]
Permute:   [1, 32, 2, 2, 64, 64] -> [1, 32, 64, 2, 64, 2]
Reshape:   [1, 32, 64, 2, 64, 2] -> [1, 32, 128, 128]

等价于 Depth2Space(block=2)，即 PixelShuffle
```

**Reorg 示例**（YOLO 中的空间到通道下采样）：

```
Reshape:   [1, 128, 64, 64] -> [1, 128, 32, 2, 32, 2]
Permute:   [1, 128, 32, 2, 32, 2] -> [1, 128, 2, 2, 32, 32]
Reshape:   [1, 128, 2, 2, 32, 32] -> [1, 512, 32, 32]

等价于 Reorg(stride=2)
```

**收益**：
- 将通用的 reshape/permute 序列识别为语义更明确的专用算子
- 后端可以针对 PixelShuffle/Reorg 生成更高效的 DMA 或卷积旁路指令

---

### 2.4 Conv1d → Conv2d（`Conv1dTo2d`）

**源码位置**：`Conv.cpp:16`

**作用**：将 1D 卷积转换为 2D 卷积。

**原理**：

许多 TPU/NPU 的卷积加速引擎只支持 2D/3D 卷积，不支持 1D。1D 卷积可以 trivial 地扩展为 2D：

- kernel shape: `[K]` → `[K, 1]`
- strides: `[S]` → `[S, 1]`
- dilations: `[D]` → `[D, 1]`
- pads: `[pad_left, pad_right]` → `[pad_left, 0, pad_right, 0]`

这样无需修改数据布局，只需改 weight 的 shape 和卷积参数即可。

## 3. 冗余消除

### 3.1 Permute 消除（`TopPermuteEliminate`）

**源码位置**：`Permute.cpp:827`

**作用**：当 `Permute` 的输入是 1D tensor 时，直接删除该 Permute。

**原理**：1D tensor 只有一个维度，任何 permute 操作都是 no-op（恒等变换）。

---

### 3.2 Permute 融合（`PermuteFuse`）

**源码位置**：`Permute.cpp:299`

**作用**：连续的两个 `Permute` 合并为一个。

**原理**：

Permute 本质上是维度索引的重排。两个连续 permute 的复合仍然是某个 permute。设第一个 permute 的 order 为 `P1`，第二个为 `P2`，则复合 order 为 `P2[P1[i]]`。

代码中通过 `permute_reset` 函数将两个不同维度的 permute 对齐到统一的维度空间（2D~5D），然后计算复合顺序，生成一个新的 `PermuteOp`。

**收益**：
- 减少一次维度重排的数据搬运
- 连续的 permute 在有些情况下可以完全抵消（如 transpose 两次回到原状）

---

### 3.3 Reshape 融合（`TopReshapeFuse`、`TopReshapeFuse2`）

**源码位置**：`Reshape.cpp:400`、`Reshape.cpp:425`

**作用**：

- `TopReshapeFuse`：`Reshape(Reshape(x))` → 直接跳到最内层的 `x`
- `TopReshapeFuse2`：如果中间夹了一个只有一个使用者的 op，可以把 op 移到 reshape 外面（`Reshape + Op → Op + Reshape`）

**原理**：

Reshape 只改变 tensor 的类型 shape，不改变底层数据的排列（假设是 row-major）。因此：

- 两个 reshape 可以直接合并为一个（或跳过中间的）
- 如果某个 elementwise op（如 Add、Mul）不依赖具体维度信息，可以先做计算再 reshape，这样后续的 reshape 可能被其他优化消除

---

### 3.4 连续 Slice + Concat 合并（`MergeSliceConcatPattern`）

**源码位置**：`Concat.cpp:422`

**作用**：多个 `Slice` 从同一张图切出**连续不重叠**的片段，再 `Concat` 拼起来 → 直接用一个覆盖全范围的 `Slice` 替代。

**图示**：

```
     -- Slice[0:10] --
    /                  \
Op ->|                  |-> Concat  =>  Op -> Slice[0:30]
    \                  /
     -- Slice[10:30] --
```

**匹配条件**：
- 所有 Slice 的**输入相同**
- 在 Concat 的 axis 上，Slice 的 offset 首尾相接
- 其他维度的 offset/steps/ends 完全一致
- step 在 axis 上为 1

**收益**：
- 消除 Concat 算子
- 消除多个 Slice 的冗余索引计算
- 如果最后只剩一个 Slice，后续还可能被完全消除

---

### 3.5 空输入/单输入 Concat 消除

**源码位置**：`Concat.cpp:595`、`Concat.cpp:619`

**`RemoveInvaidShapeConcatInput`**：
- 如果 Concat 只有一个输入，直接删掉 Concat，使用者指向该输入

**`RemoveInvaidConcatSlice`**：
- 遍历 Concat 的输入，如果某个输入的元素个数为 0（空 tensor），直接过滤掉
- 示例：`Concat(0, X) → Concat(X)`，`Concat(None, X) → Concat(X)`

---

### 3.6 无效 Reshape 消除（`InValidReshapeMergePattern`）

**源码位置**：`Reshape.cpp:291`

**作用**：如果 `Reshape` 的输出 shape 为空（`size() == 0`，即 scalar 或 invalid），且使用者是 `UnsqueezeOp`，直接跳过 Reshape，让 Unsqueeze 操作原始输入。

**原理**：0 维 reshape 通常是 importer 阶段的中间产物，对实际计算无意义，应尽早消除。

## 4. 存储优化

### 4.1 Weight 全同值压缩（`WeightToConst`）

**源码位置**：`Weight.cpp:13`

**作用**：当一个 `WeightOp` 的所有元素值**完全相同**，且只有一个使用者时，把 weight 压缩为**单元素 tensor**。

**示例**：

```
# 原 weight: [1, 64, 112, 112] 全 1
# 压缩后:    [1] 值为 1.0
```

**原理**：

单元素 tensor 在使用时会被**广播**（broadcast）到目标 shape。TPU/NPU 的广播通常由硬件在加载时自动完成，无需把完整的重复数据存到内存中。

**匹配条件**：
- 只有一个使用者（避免影响其他需要完整 shape 的使用者）
- 使用者必须有 `SupportConstant` trait（支持常量/broadcast 输入）
- 非 weight 输入的形状必须与输出形状相同（避免复杂 broadcast 场景）
- 所有数据元素严格相等

**收益**：
- 存储空间：从 `N*C*H*W` 个 float 降到 **1 个 float**
- 对于全 0 bias、全 1 scale 等常见参数，效果极其显著

---

### 4.2 全 Weight Concat 编译期合并（`ConvertLoadWeightConcatToLoadWeightPattern`）

**源码位置**：`Concat.cpp:531`

**作用**：如果 `Concat` 的**所有输入都是 WeightOp**，在编译期读取所有 weight 数据、拼接、生成一个新的 WeightOp，完全消除 Concat。

**匹配条件**：
- 所有输入都是 `WeightOp`
- 输出存储类型为 F32 或 F16
- Weight 形状为 3D `[N, H, W]`

**原理**：

Concat 在运行时的行为只是内存拷贝（把多个 tensor 按某个 axis 拼接）。如果所有输入都是编译期常量，完全可以提前算好，生成一个大的常量 weight。运行时直接加载这个 weight，无需执行 Concat 操作。

**收益**：
- 完全消除运行时的 Concat 操作
- 减少模型执行时的内存分配和拷贝

## 5. 图结构重排

### 5.1 Add-Reshape 交换（`TopAddReshapeSwap`）

**源码位置**：`Reshape.cpp:335`

**作用**：将 `Add` 两个输入分别 `Reshape` 后再相加的模式，改为先 `Add` 再 `Reshape`。

**图示**：

```
A -> Reshape --\
               + Add -> Reshape -> LayerNorm/MatMul
B -> Reshape --/

=>

A --\
    + Add -> Reshape -> Reshape -> LayerNorm/MatMul
B --/
```

**适用场景**：Swin Transformer 等网络中的残差连接。

**原理**：

Elementwise 的 `Add` 与 `Reshape` 是可交换的（因为 reshape 不改变数据的线性顺序，而 elementwise add 也不依赖维度信息）。把 Reshape 后移后，两个输入的 Reshape 可能完全相同，可以进一步融合或消除。

---

### 5.2 Softmax 与 Permute 交换（`TopMoveSoftmaxAfterPermute`）

**源码位置**：`Permute.cpp:845`

**作用**：将 `Permute -> Softmax -> Permute` 中的 Softmax 移到 Permute 外面。

**图示**：

```
Permute{0,3,1,2} -> Softmax -> Permute{0,3,2,1}
        |
        v
Permute{0,2,1,3} -> Softmax
```

**适用场景**：YOLOv8 等检测头中的类别概率计算。

**原理**：

Softmax 是沿着某个轴做归一化。如果它前后被两个特定的 Permute 包裹，可以通过调整 Permute 的顺序，把 Softmax 提到一个更简单的位置。这样后续的 Permute 可能被消除或与前面的 Permute 融合。

## 6. 总结

TPU-MLIR 的 `Top/Canonicalize` 层优化遵循以下几个核心思想：

| 优化类型 | 代表 Pattern | 核心思想 |
|---------|-------------|---------|
| **算子融合** | Conv1x1+Convkxk、MatMul+Add、BatchNorm→Scale | 减少内存搬运，利用硬件融合指令能力 |
| **算子转换** | Einsum→MatMul、Concat→Depth2Space、Permute→PixelShuffle | 将灵活/复杂算子映射到硬件原生支持的算子 |
| **冗余消除** | Permute消除/融合、Reshape融合、Slice+Concat合并 | 删除无意义或重复的数据变换操作 |
| **存储优化** | Weight全同值压缩、全Weight Concat预计算 | 编译期常量折叠，减少运行时内存占用 |
| **图重排** | Add-Reshape交换、Softmax-Permute交换 | 调整算子顺序，为后续融合创造条件 |

这些 canonicalization pattern 大多在 **shape inference 之后、lowering 之前**执行，目的是把前端导入的"原始" IR（通常来自 ONNX/Torch，冗余较多）整理成更简洁、更利于后端 codegen 的形式。
